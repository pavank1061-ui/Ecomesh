What do I add here?

Add another person who has opened EchoMesh on their own device. Both of you export your public bundle and import each other's bundle. If you do not have another EchoMesh device/person to exchange bundles with, leave this empty; there is no real recipient to select yet.

Use case: two people nearby who need to exchange encrypted emergency messages over sound without a messaging server.

!
About fingerprint verification

The fingerprint is a short summary of the public keys. Compare it directly with that person through a trusted channel before accepting. This helps catch a swapped or incorrect key. If you cannot compare it, do not mark the key trusted.

LOCAL SELF-CHECK

Diagnostics

Browser capabilities are not proof of a successful acoustic link.

Physical-device test procedure

  1. Serve the built application over HTTPS (or use localhost) on two supported devices; open it once online so assets are cached.
  2. On each device, open Security & identity and export the public bundle. Import each other's bundle and compare the displayed fingerprints in person.
  3. When a verified modem is integrated, enable receive on Device B, then transmit a short message from Device A.
  4. Check that B decrypts it, then send a signed acknowledgement acoustically before A marks it delivered.
  5. Repeat offline; test a wrong key and corrupted packet. Reload both devices and verify identity and queues persist.

This prototype has not completed a physical-device transfer. Microphone access requires HTTPS or localhost, and this build has no acoustic modem.
